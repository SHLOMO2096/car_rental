# אפיון: אירועים, תמונות ומסמכים

מסמך אפיון למודול שמטפל בשלושה חסרים קשורים: **תיעוד מצב הרכב**, **ניהול אירועים** (תאונה, נזק, גניבה), ו**מסמכים עם תוקף**.

הבסיס הוא מה שכבר קיים — `CarBlock` (השבתה זמנית), `services/google_drive.py` ו-`log_audit_event` — ולא מודול נפרד שחי לצדם.

---

## 1. למה עכשיו

המערכת יודעת **מי הזמין איזה רכב ומתי**. היא לא יודעת:

| שאלה | המצב היום |
|---|---|
| באיזה מצב הרכב נמסר? | תמונות בתיקייה שטוחה, בלי לדעת אם צולמו במסירה או בהחזרה |
| כמה ק״מ נסע? | לא נשמר |
| מה קרה בתאונה? | לא קיים כלל |
| מתי פג הביטוח? | לא קיים. `Car.test_date` הוא `String(50)` שנשאב מדוח |
| מתי פג רישיון הנהיגה של הלקוח? | לא קיים |

שני הראשונים הם **מקור הוויכוחים הכספיים**. השלישי הוא **חשיפה משפטית וביטוחית**. הרביעי והחמישי הם **עבירה** — השכרת רכב שהביטוח שלו פג, או השכרה לבעל רישיון פג.

---

## 2. מה קיים היום, ומה שבור בו

### 2.1 תמונות

```python
Booking.drive_link = Column(String(2048))
```

הקישורים נשמרים **כמחרוזת אחת מופרדת בפסיקים**. מכאן נגזר:

- **אי אפשר למחוק תמונה.** המחרוזת רק גדלה.
- **אין מטא-דאטה.** לא מי צילם, לא מתי, לא באיזה שלב, לא מה רואים.
- **תקרה של 2048 תווים.** קישור Drive הוא כ-60 תווים, כלומר כ-30 תמונות ואז שקט — ללא שגיאה. הזמנה ארוכה עם תיעוד יסודי תגיע לשם.
- הכול בתיקייה שטוחה אחת, בשם `Booking_{id}_{car}_{customer}_{ts}.jpg`.

### 2.2 באג שיש לתקן לפני הכול

בתוך נקודת הקצה של **העלאת תמונה** (`backend/app/routers/bookings.py`, סביב שורה 598):

```python
previous_active = db.query(Booking).filter(
    Booking.car_id == booking.car_id,
    Booking.status == BookingStatus.active,
    Booking.id != booking.id
).all()
for prev in previous_active:
    if prev.start_date <= booking.start_date:
        prev.status = BookingStatus.completed
```

**העלאת תמונה מסמנת בשקט הזמנות אחרות של אותו רכב כ"הושלמה".**

בלי אישור, בלי `log_audit_event` על ההזמנות שהשתנו, ובלי התראה למנהל. זה סותר את העיקרון המוצהר של המערכת — *nothing significant happens silently* — ומסתיר שינוי סטטוס בתוך פעולה ששמה "העלאת קובץ".

**ההמלצה:** להוציא את הלוגיקה הזו מנקודת הקצה. סגירת הזמנה קודמת היא פעולה בפני עצמה; אם רוצים אותה אוטומטית, שתהיה מפורשת, מתועדת ב-audit, ומופעלת מאירוע **החזרת רכב** ולא מהעלאת קובץ.

### 2.3 הרשאות

ההעלאה דורשת `BOOKINGS_VIEW` — כלומר **כל מי שרואה הזמנה יכול להעלות אליה קבצים**. זו ההרשאה הרחבה ביותר במערכת.

## 3. המודל

שלוש ישויות חדשות. שתיים מהן פולימורפיות, בדפוס שכבר קיים כאן (`PriceRule.entity_type` / `entity_value`).

### 3.1 `Attachment` — קובץ

טבלה אחת לכל הקבצים במערכת, במקום עמודת קישורים לכל ישות.

```python
class AttachmentOwner(str, enum.Enum):
    booking  = "booking"
    car      = "car"
    customer = "customer"
    incident = "incident"

class AttachmentStage(str, enum.Enum):
    pickup   = "pickup"      # מסירה
    ret      = "return"      # החזרה
    incident = "incident"    # אירוע
    document = "document"    # מסמך (ראו 3.3)
    other    = "other"

class Attachment(Base):
    id            = Integer, pk
    owner_type    = Enum(AttachmentOwner), index
    owner_id      = Integer, index
    stage         = Enum(AttachmentStage)
    kind          = String(20)      # image / pdf
    drive_file_id = String(128)     # למחיקה אמיתית ב-Drive
    drive_link    = String(512)
    file_name     = String(255)
    content_type  = String(100)
    size_bytes    = Integer
    caption       = String(500)     # "שריטה בדלת ימין אחורית"
    taken_at      = DateTime        # מתי צולם, לא מתי הועלה
    uploaded_by   = FK users
    created_at    = DateTime
    deleted_at    = DateTime        # מחיקה רכה, כמו הזמנות
    deleted_by    = FK users
```

**למה `drive_file_id`:** בלעדיו אי אפשר למחוק קובץ מ-Drive. היום נשמר רק הקישור.

**אינדקס:** `(owner_type, owner_id, stage)`.

### 3.2 `Incident` — אירוע

תאונה אינה אוסף תמונות. היא ישות עם מחזור חיים, שמקשרת רכב, הזמנה, לקוח, כסף וזמן.

```python
class IncidentType(str, enum.Enum):
    accident = "accident"   # תאונה
    damage   = "damage"     # נזק ללא תאונה (שריטה, שמשה)
    theft    = "theft"      # גניבה
    fault    = "fault"      # תקלה מכנית
    other    = "other"

class IncidentStatus(str, enum.Enum):
    open      = "open"        # נפתח
    at_garage = "at_garage"   # במוסך
    assessor  = "assessor"    # ממתין לשמאי
    insurance = "insurance"   # בטיפול ביטוח
    closed    = "closed"      # נסגר

class Incident(Base):
    id                  = Integer, pk
    car_id              = FK cars, index, NOT NULL
    booking_id          = FK bookings, nullable, index   # מי החזיק ברכב
    customer_id         = FK customers, nullable, index
    car_block_id        = FK car_blocks, nullable        # ההשבתה שנוצרה
    type                = Enum(IncidentType)
    status              = Enum(IncidentStatus), index
    occurred_at         = DateTime, index                # מתי קרה
    reported_at         = DateTime                       # מתי דווח
    location            = String(255)
    description         = Text
    # צד שלישי
    third_party_name    = String(255)
    third_party_phone   = String(50)
    third_party_plate   = String(20)
    third_party_insurer = String(120)
    # מספרי אסמכתא
    police_report_no    = String(60)
    claim_no            = String(60)
    # כסף
    estimated_cost      = Float
    actual_cost         = Float
    deductible          = Float        # השתתפות עצמית
    charged_customer    = Float        # מה חויב מהלקוח
    created_by          = FK users
    # + מחיקה רכה
```

**הקישור ל-`CarBlock`:** פתיחת אירוע מציעה מיד להשבית את הרכב. ההשבתה היא `CarBlock` רגיל עם `reason="accident"`, ו-`incident.car_block_id` מצביע עליה. כך הרכב נעלם מרשת הזמינות ואי אפשר להזמין אותו — **בלי לוגיקת חסימה חדשה**, על הקוד שכבר נכתב ונבדק.

**סגירת אירוע** מציעה לבטל את ההשבתה.

### 3.3 `Document` — מסמך עם תוקף

מסמך אינו רק קובץ; הוא **תאריך תפוגה שמישהו צריך לשמור עליו**.

```python
class DocumentKind(str, enum.Enum):
    # רכב
    car_license     = "car_license"      # רישיון רכב
    insurance_third = "insurance_third"  # ביטוח חובה
    insurance_full  = "insurance_full"   # ביטוח מקיף
    inspection      = "inspection"       # טסט
    # לקוח
    drivers_license = "drivers_license"  # רישיון נהיגה
    id_card         = "id_card"          # ת.ז / דרכון
    # הזמנה
    contract        = "contract"         # חוזה שכירות חתום
    handover        = "handover"         # טופס מסירה
    other           = "other"

class Document(Base):
    id            = Integer, pk
    owner_type    = Enum(AttachmentOwner)   # car / customer / booking
    owner_id      = Integer, index
    kind          = Enum(DocumentKind), index
    number        = String(100)             # מספר פוליסה / רישיון
    issued_on     = Date
    expires_on    = Date, index             # הלב של הטבלה
    issuer        = String(120)             # חברת ביטוח / משרד הרישוי
    attachment_id = FK attachments          # הסריקה עצמה
    note          = Text
    # + מחיקה רכה
```

**`Car.test_date` מהוגר לכאן** כ-`Document(kind=inspection)` עם `expires_on` אמיתי מסוג `Date`. העמודה הישנה נשארת לקריאה בלבד עד שהמיגרציה מאומתת, ואז יורדת.

## 4. חוקי אכיפה

כאן המודול מפסיק להיות ארכיון ומתחיל להיות שימושי.

### 4.1 חסימה קשה

| מצב | תוצאה |
|---|---|
| ביטוח חובה או טסט של הרכב פג **בתוך טווח ההזמנה** | יצירת הזמנה **נחסמת** |
| רישיון הנהיגה של הלקוח פג בתוך הטווח | אזהרה (ראו החלטה 2) |
| הרכב תחת `CarBlock` | כבר מיושם |

החסימה נכנסת לצד `_reject_if_blocked` שכבר קיים ב-`bookings.py` — אותו דפוס, הודעה משלה.

### 4.2 אזהרה רכה

| מצב | תוצאה |
|---|---|
| מסמך פג בתוך 30 יום | אזהרה בדשבורד ובטופס ההזמנה |
| הזמנה נסגרת בלי תמונות החזרה | אזהרה בעת השלמת ההזמנה |
| ק״מ החזרה נמוך מק״מ מסירה | אזהרה — טעות הקלדה |

### 4.3 תיעוד מסירה והחזרה

שדות חדשים על `Booking`:

```
pickup_km    Integer      return_km    Integer
pickup_fuel  Integer      return_fuel  Integer   # 0–8 שמיניות, כמו מחוון
pickup_at    DateTime     return_at    DateTime  # מתי בוצע בפועל
pickup_by    FK users     return_by    FK users
```

`return_km - pickup_km` הוא הקילומטראז׳ של ההשכרה. סכימה על פני הזמנות נותנת את הק״מ של הרכב — ומכאן מועדי טיפול.

## 5. איפה זה יושב בממשק

זו השאלה שנשאלה, וזו התשובה שאני ממליץ עליה.

### 5.1 לשונית חדשה בניווט: "אירועים"

**כן, מודול נפרד.** אירוע חוצה רכב, הזמנה, לקוח וזמן — הוא לא שדה בכרטיס הרכב. מנהל צריך לשאול "מה פתוח אצלי עכשיו", וזו שאלה של רשימה, לא של כרטיס.

מיקום בסרגל: **אחרי "הזמנות", לפני "לוח שנה"** — לפי סדר התדירות.

המסך: רשימת אירועים עם סינון לפי סטטוס, כרטיס לכל אירוע (רכב, לקוח, תאריך, עלות, סטטוס), ומסך אירוע בודד עם ציר זמן, תמונות ומסמכים.

תג מונה על פריט הניווט כשיש אירועים פתוחים — כמו ה-badge שכבר קיים ב-`ActionMenu`.

### 5.2 כרטיס הרכב → לשונית "מסמכים וכשירות"

מסך הרכבים היום הוא רשת כרטיסים בלבד. אני ממליץ להפוך לחיצה על שם הרכב ל**מסך רכב** עם שלוש לשוניות:

| לשונית | תוכן |
|---|---|
| פרטים | מה שיש היום בטופס העריכה |
| מסמכים וכשירות | טסט, ביטוח חובה, ביטוח מקיף, רישיון רכב — כל אחד עם תוקף, סטטוס צבעוני וסריקה |
| היסטוריה | אירועים, השבתות, ק״מ מצטבר |

**בכרטיס ברשת** — נקודה אדומה קטנה כשיש מסמך פג או שפג בקרוב. היום `טסט עד:` מוצג באדום **תמיד**, גם כשהתוקף רחוק. זה צועק ולא מודיע.

### 5.3 כרטיס הלקוח → לשונית "מסמכים"

רישיון נהיגה עם תוקף, ת.ז. ובטופס ההזמנה, ליד שם הלקוח — **תג ירוק/אדום** של תוקף הרישיון. הסוכן רואה את זה לפני שהוא ממשיך, לא אחרי.

### 5.4 ההזמנה → `PhotoMenu` הופך ל"קבצים"

הרכיב הקיים ב-`components/photos/PhotoManagement.jsx` נשאר, ומקבל **שלב**:

```
מסירה   (3)
החזרה   (0)   ← אדום כשההזמנה הסתיימה
מסמכים  (1)
```

הגלריה מקבצת לפי שלב, ומאפשרת **מחיקה** — שאינה אפשרית היום.

### 5.5 מסך "מסירה / החזרה"

הפעולה שהכי חסרה. מכפתור בשורת ההזמנה:

```
מסירה →  ק״מ | דלק | תמונות סבב | הערות | חתימה → חוזה PDF
החזרה →  ק״מ | דלק | תמונות סבב | נזק חדש? → פתיחת אירוע
```

**"נזק חדש?" בהחזרה פותח אירוע מתוך המסך** — עם הרכב, ההזמנה והלקוח כבר ממולאים. זה הרגע שבו הנזק מתגלה, וזה הרגע שבו התיעוד שווה משהו.

מותאם לטלפון: זה נעשה בחניה, על מכשיר נייד, לא בשולחן.

### 5.6 הדשבורד

- רכב תחת אירוע פעיל — כבר מפוספס בגריד דרך `CarBlock`. תווית "תאונה".
- **כרטיס KPI חדש: "דורש טיפול"** — מסמכים שפגו, אירועים פתוחים, החזרות ללא תיעוד. מספר אחד שנפתח לרשימה.

## 8. מסלול המעבר מ-`drive_link`

בלי הפסקת שירות:

1. `Attachment` נוצרת. העלאות **חדשות** נכתבות לשתיהן.
2. סקריפט הגירה מפרק כל `drive_link` לפי פסיקים ל-`Attachment` עם `stage="other"` — אין דרך לדעת מה היה מסירה ומה החזרה, וזה בסדר.
3. הקריאה עוברת ל-`Attachment`.
4. אחרי אימות — הכתיבה הכפולה נפסקת, והעמודה יורדת במיגרציה נפרדת.

**`drive_file_id` חסר בהיסטוריה.** קבצים ישנים לא יהיו ניתנים למחיקה מ-Drive. אפשר להשלים בסריקת התיקייה לפי שם הקובץ, או לוותר — זה נתון היסטורי.

## 10. החלטות שצריכות אישור

1. **אחסון.** להישאר ב-Google Drive, או לעבור לאחסון אובייקטים (S3 / MinIO)? Drive עובד, אבל חתימות, PDF ומחיקה יהיו נוחים יותר במקום שאנחנו שולטים בו. *המלצתי: להישאר ב-Drive לשלבים 1–4, ולשקול מעבר רק אם החתימה בשלב 5 תדרוש זאת.*
2. **חסימה קשה על מסמך פג** — לחסום יצירת הזמנה, או רק להזהיר? *המלצתי: לחסום על ביטוח וטסט, להזהיר על רישיון נהיגה — הלקוח יכול להביא רישיון מעודכן למסירה.*
3. **מסך רכב נפרד** (5.2) הוא שינוי מבני במסך הרכבים. לאשר?
